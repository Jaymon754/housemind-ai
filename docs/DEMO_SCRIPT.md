# HouseMind AI — 5–8 分钟演示视频脚本

> 目标时长：**约 5 分 37 秒**（可压缩到 5:10，或扩展到 7:30）  
> 画质：1920×1080，30fps；浏览器 100% 缩放；隐藏书签栏  
> 语速：约 240–260 字/分钟；不要逐字念界面
>
> 仓库内的 `HouseMind_AI_Demo_1080p.mp4` 由真实 UI 截图与本地中文 TTS 合成，便于稳定交付；如比赛要求现场录屏，可按本脚本重录。

## 录制前准备

1. 清理演示数据，只保留一条精选会话：

```bash
rm -f backend/data/housemind.db
find backend/data/uploads -type f -delete
```

2. 启动：

```bash
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

3. 浏览器打开 `http://127.0.0.1:8000`，确认：

- 左下角模型徽标显示 `XGBOOST · LIVE`；
- Agent 页显示 `DEEPSEEK` / `DeepSeek 在线`（配置密钥时）；无密钥时显示 `LOCAL PLANNER`；
- 知识库显示 18 篇文档、71 个片段；
- 图像页本地演示图可加载。

4. 录屏工具：OBS / Screen Studio / QuickTime；麦克风单独测试；关闭通知。
5. 鼠标移动放慢，点击前停顿 0.3 秒；重要数字用鼠标画圈或放大。

## 分镜

### 0:00–0:25 开场：问题不是缺一个价格

**画面**：数据驾驶舱首屏，缓慢下移到 KPI 与地图。

**旁白**：

> 买房时，我们最常得到的是一个价格。  
> 但价格是不是合理？为什么是它？如果出租，每月要补多少？模型错的时候，会错多少？  
> HouseMind AI 想做的，不是再给一个数字，而是把一条可核对的决策链摊开。  
> 它使用金县 2014 到 2015 年的两万一千多套真实成交，覆盖估值、解释、投资、知识、图像和 Agent 七个模块。

**操作**：鼠标划过 KPI「21,418 成交」「$450K 中位价」「13 个月」。

### 0:25–0:59 数据驾驶舱：先看市场，再看房

**画面**：`/`，地图与价格分布。

**旁白**：

> 驾驶舱先回答“这是怎样的市场”。  
> 这里是金县 21,418 套清洗后的成交，中位价约 45 万美元，数据截止 2015 年 5 月。  
> 地图上的每一个点都是真实成交；颜色越浅，价格越高。右侧是邮编价格榜与区域结构。  
> 注意，这不是当前市场，而是历史样本。所有后续估值都受这个范围约束。

**操作**：点击地图上一个点（如有 tooltip），滚动到「区域结构」表格。

### 0:59–1:51 智能估值：价格是一个区间

**画面**：`/valuation`。

**操作**：

1. 保留默认邮编 `98115`；
2. 面积 `1840`，卧室 `3`，卫浴 `2`，建造年份 `1985`，等级 `7`，挂牌价 `599000`；
3. 等待自动分析。

**旁白**：

> 我们估一套 98115 的 1,840 平方英尺住宅，挂牌 59.9 万。  
> 模型给出约 **57.41 万美元**，但主视觉是 **48.39 万到 66.03 万** 的 80% 参考区间。  
> 区间不是拍脑袋的上下 10%，而是 5 折袋外残差的分位数，所以它可以不对称。  
> 下面的 SHAP 把价格拆开：面积、纬度、邮编基准在推高；建筑等级、房龄在拉低。  
> 每一项都有金额和原始特征值。基准值加所有贡献，应该等于模型输出——这是可加性校验。  
> 再往下是同邮编可比成交、市场位置、what-if 和模型假设。  
> 如果挂牌价落在区间外，页面会提示你先核查数据与房屋状况，而不是直接说“捡漏”。

**操作**：把面积从 1840 拖到 2200，指出估值与区间实时变化；展开一条可比成交。

### 1:51–2:45 投资决策：把租金拆成现金流

**画面**：`/investment`。

**旁白**：

> 估值只回答“值多少”，投资还要回答“养不养得起”。  
> 默认是一套 57 万美元的西雅图北区联排，月租 2,950，首付 25%，利率 6.5%。  
> 月供约 2,702 美元；扣除税费、保险、HOA、维护和空置后，NOI 约 2 万美元。  
> 结果是：月现金流 **负 1,000 美元**，DSCR **0.63**，盈亏平衡入住率 **128.9%**。  
> 我们没有把默认值调成“好看”的正现金流。负现金流就是负现金流，产品应该先告诉用户真相。  
> 右侧瀑布图从租金走到净现金流；下方是 5 年 schedule、退出回款、租金×利率敏感性。  
> 把租金提高到 4,200，或首付提高到 35%，可以看到 DSCR 如何变化。

**操作**：点击「乐观」情景；再点「基准」；把月租改为 4200，指出月现金流与 DSCR。

### 2:45–3:30 AI 顾问：一个会用工具的 Agent

**画面**：`/agent`。

**操作**：点击示例问题「预算 40 万美元，在 98052 买一套 3 室 2 卫投资房，出租值得吗？」

**旁白**：

> Agent 不是直接编一段话。它先规划，再调用工具。  
> 这里可以看到三次真实调用：房价预测、区域市场分析、投资回报测算；每次都有参数、耗时和结果摘要。  
> 它给出的价格、区间、月供、DSCR 都来自工具，不是语言模型即兴生成。  
> 当前配置了 DeepSeek，界面标注 DeepSeek Agent 与 Function Calling。  
> 没有密钥时，同一个界面会回退到本地规划器；工具、事件流和轨迹保持不变。  
> 刷新页面，工具轨迹仍然保留。

**操作**：刷新页面，展开「工具调用轨迹」，指出历史记录仍在。

### 3:30–4:09 知识库：回答必须带出处

**画面**：`/knowledge`。

**旁白**：

> 知识库有 18 篇方法文档、71 个片段。  
> 它用 Chroma 向量召回和 BM25 字面检索混合排序，回答必须带编号引用。  
> 我们问一个最容易被含糊回答的问题：DSCR 低于 1.25 意味着什么？  
> 回答会先给结论，再给公式与引用；点开引用可以看到原文。  
> 如果是“如何更换汽车轮胎”这种超纲问题，它会明确说没有找到，而不是拿最相似的段落硬答。

**操作**：输入「如何更换汽车轮胎？」，展示拒答；再点一篇文档打开 drawer。

### 4:09–4:46 图像分析：看见，但不越界

**画面**：`/vision`。

**旁白**：

> 上传一张室内照片，系统先读取亮度、色温、饱和度、边缘密度和主色板。  
> 当前演示已接入 Qwen3-VL，能进一步识别房间类型、装修风格、可见材质和置信度。  
> 它只描述照片里看得见的内容，不会断言结构安全、面积或产权。  
> 没有视觉 Key 时，系统回退到本地信号，并明确显示语义能力未启用，而不是伪造置信度。  
> 右侧是现场核对清单：面积、产权、渗漏、电路、噪音，这些必须由人或持牌检查完成。

**操作**：拖入 `frontend/public/demo/interior.jpg`，指出「远程多模态」、房间类型/风格/置信度，以及边界列表。

### 4:46–5:15 研究实验室

**画面**：`/research`。

**旁白**：

> 最后，研究页把模型摊开：Ridge、随机森林、XGBoost 的 MAE 对比；全局 SHAP；区间覆盖率；  
> 以及更严格的未见邮编泛化——MAE 从 5.95 万升到 9.51 万。  
> 我们展示这个下降，因为它比只报一个漂亮分数更诚实。  
> HouseMind AI 不是要替代评估师或理财顾问，而是让每一次房产决策，都有数据、有区间、有解释、有边界。  
> 谢谢观看。

**操作**：缓慢滚动研究页，停在「未见邮编」卡片与「限制」列表。

### 5:15–5:37 收尾

**画面**：品牌收尾卡。

**旁白**：

> HouseMind AI 不是要替代评估师或理财顾问，而是让每一次房产决策，都有数据、有区间、有解释、有边界。读懂市场，再决定。谢谢观看。

## 备用方案

- **没有 DeepSeek 密钥**：按脚本正常录，明确说“本地规划器”；不要假装 LLM。
- **网络慢**：提前预生成会话，录屏时用 `?conversation=<id>` 直接打开；但至少现场演示一次估值与投资。
- **Agent 超时**：切到已保存会话，展示轨迹；再补录一次完整调用。
- **图像远程不可用**：只用本地模式，强调边界；不要切换到未配置的远程。
